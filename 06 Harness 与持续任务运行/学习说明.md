# 06 Harness 与持续任务运行

先看 `课件/` 中的 PDF，再按 06A～06C 的顺序打开 `Notebook/`。

| 实践 | 内容 | 运行条件 |
| --- | --- | --- |
| [06A](Notebook/01-state-and-context.ipynb) | 保存任务状态，重建模型上下文，检查旧修订冲突 | 本地 SQLite；使用第 4、5 节源码，无需联网 |
| [06B](Notebook/02-interrupt-and-resume.ipynb) | 跨进程续跑、中断窗口、预算和权限边界 | 本地 MCP 只读工具；教学动作回放，无需模型请求 |
| [06C](Notebook/03-trace-and-live-run.ipynb) | 用事件、产物哈希和源码核查一次历史运行 | pandas；读取本节脱敏实验记录，不发起模型请求 |

从资料根目录启动 JupyterLab，保留第 2、4、5 节及本节的目录。先按首页说明安装第 5 节依赖，再安装[本节依赖](requirements.txt)。`代码/` 是课程运行程序和自检；Notebook 会将新运行结果写入根目录 `.local/student-runs/l06/`。

06A、06B 使用教学回放和本地只读工具；06C 读取 `数据/实验记录/deepseek-harness.json` 中的历史运行摘要。该记录保留离线诊断所需的事件和工具产物，已移除完整模型对话及与实验无关的工作状态。其源码快照哈希属于历史运行；学生版 Skill 文件经过调整，因此 Notebook 分开核对未改动的示例文件。

默认运行不会发起收费模型请求。命令行程序只有显式指定 `--mode deepseek` 并配置自己的 `DEEPSEEK_API_KEY` 时才会请求模型；开启前先确认账号可用模型及费用。历史回答用于练习证据核查，不保证内容完全正确。

本节 Harness 场景设计作业的要求和报告模板在教学平台发布，仓库只提供正课资料。
